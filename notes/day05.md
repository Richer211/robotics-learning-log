## What I Learned（中文）

### 为什么 `build/` 和 `**/build/` 要忽略？

- 这是 cmake 编译后产生的机器码/中间文件；已有 `.cpp` / `.hpp` 源码，可随时 `cmake && make` 重新生成
- 提交会占用空间，且对协作没有价值

### 为什么 `sensor_log.txt` 要忽略？

- 程序运行输出的日志，重新运行 demo 即可生成

### `__pycache__/`、`.DS_Store` 分别是什么？为什么要忽略？

- `__pycache__/`：Python 自动生成的字节码缓存，本地环境相关
- `.DS_Store`：macOS 给文件夹自动生成的隐藏元数据（图标位置、视图设置等）
- 都不应进版本库



### `practice/day04/random_demo` 应不应该提交？

- 不应该。这是 `g++` 编译出的二进制，源码是 `random_demo.cpp`，需要时重新编译即可



### README 里构建命令在哪？

- 在 `[README.md](../README.md)` 的 **Build & Run (Week 1)** 一节
- Python 命令在 `python_practice/` 目录下执行；C++ 在 `cpp_practice/fake_sensor_cpp/` 下执行



### `.gitignore` 注释写法（重要）

- 注释必须**单独一行**，以 `#` 开头
- ❌ 错误：`build/  # 编译后的文件`（Git 会把 `#` 后面也当成规则的一部分，导致忽略失效）
- ✅ 正确：上一行写 `# 编译后的文件`，下一行写 `build/`

| English         | 中文                                 |
